# Тестовые данные (только для локальной разработки)

Заполняет базы реалистичной историей за 16 недель, чтобы было что смотреть на графиках
и в аналитике. **Ваш аккаунт сохраняется**, всё остальное очищается и создаётся заново.

## Запуск

```bash
cd infra
docker compose up -d postgres     # один раз после обновления compose: подключится папка /seed
docker exec vegas-postgres sh /seed/seed.sh your@email.ru
```

Сид можно запускать сколько угодно раз — результат каждый раз одинаковый.
Чтобы аналитика пересчиталась, должны быть запущены Kafka, **workout-service** и **analytics-service**.
Через 5–20 секунд после сида проверьте `GET :8083/api/records`.

## Что получится

| Где | Что |
|---|---|
| user_db | остаётся только ваш пользователь; профиль заполнен (что вы уже ввели — сохраняется); вес за 16 недель |
| workout_db | 48 завершённых тренировок по 4 готовым комплексам; ваши комплексы и свои упражнения удалены |
| analytics_db | очищается и заполняется заново из событий Kafka (outbox -> Kafka -> analytics) |

Сценарии для проверки аналитики:

| Упражнение | Что увидите |
|---|---|
| Жим лёжа | рост ~10 недель, затем **плато** -> рекомендация разгрузки |
| Приседания со штангой | последняя тренировка: объём резко вырос, вес просел, RPE 9.5 -> **риск HIGH** |
| Становая тяга | стабильный рост -> **рекорды**, рекомендация "продолжай" |
| все | 9-я неделя — **разгрузочная** (70% веса, вдвое меньше подходов) — провал на графике |

## Файлы

| Файл | БД | Что делает |
|---|---|---|
| `seed.sh` | — | находит пользователя по email и запускает скрипты по порядку |
| `03-analytics.sql` | analytics_db | очищает статистику |
| `01-user.sql` | user_db | удаляет других пользователей, заполняет профиль и вес |
| `02-workouts.sql` | workout_db | тренировки + события в outbox. **Сгенерирован** — не править руками |
| `generate_workouts.py` | — | генератор `02-workouts.sql`: `python infra/seed/generate_workouts.py` |

## Почему не Liquibase-миграция

Миграции выполняются везде, где запускается сервис, — в том числе на сервере с настоящими
пользователями. Удаление данных в миграции однажды очистило бы прод. Поэтому сид — отдельный
скрипт, который запускают только руками и только локально.
(Альтернатива — Liquibase `contexts: dev`, но ручной запуск нагляднее и безопаснее.)
